# Agnia Bluesky Suite

Единое Windows-приложение для нескольких аккаунтов Bluesky: лайки, фолловинг, публикации, очередь, календарь, экспорт и резервные копии. Все операции выполняются через API, без браузера.

## Скачать и обновить

В [Releases](https://github.com/Kandelsbreit/agnia-bluesky-suite/releases/latest) скачайте `AgniaBlueskySuite-v1.3.1-windows-x64.zip`, распакуйте и запустите `AgniaBlueskySuite.exe`.

Для обновления полностью завершите предыдущую версию через меню трея и замените EXE в прежней папке. Не удаляйте папку `data`: в ней находятся аккаунты, ключ, очередь, черновики и вложения. Перед переходом на новую схему база автоматически копируется в `data/backups`. При переносе на другой компьютер удобнее использовать защищённую резервную копию из настроек.

EXE не подписан сертификатом издателя. Контрольные суммы EXE и ZIP находятся в `SHA256SUMS.txt`.

## Разделы

- **Лайки:** домашняя лента, рекомендации, поиск; несколько аккаунтов; пропуск своих постов, ответов, репостов и ранее поставленных лайков; пауза, остановка, интервалы между циклами.
- **Фолловинг:** импорт handle и ссылок, проверка существующей подписки, лимит, остановка и история действий.
- **Постинг:** черновик для каждого аккаунта; предпросмотр; текст, до четырёх изображений, одно MP4-видео или карточка ссылки; описания alt; ссылки, хештеги и упоминания. Публикация сейчас проходит через постоянную очередь отправок.
- **Очередь:** редактирование текста и вложений, поиск без учёта регистра, массовое выделение и удаление, изменение порядка, пропуск, повторная проверка отправки, история с переходом к опубликованному посту. Пропущенный текст можно вернуть из истории.
- **Календарь:** месяц и список постов выбранного дня по всем аккаунтам; точная дата задаётся в редакторе; время показывается в часовом поясе Windows. Время обычной очереди отмечено `~`: это оценка, без jitter и сетевых задержек.
- **Экспорт:** собственные текстовые посты без репостов; фильтр дат, ответы, дедупликация; TXT для очереди и отдельный экспорт для AI. Отмена не перезаписывает уже существующий файл неполным результатом.
- **Аккаунты:** единый список профилей и App Password. Для очереди и автоматизации используются общие сессии аккаунта с сохранением и обновлением токенов.
- **Настройки:** темы, трей, автозапуск, задержки, журнал, резервное копирование и восстановление.

## Первый запуск

1. Создайте App Password в настройках Bluesky: Settings → Privacy and security → App passwords.
2. Добавьте handle и App Password в разделе «Аккаунты».
3. Для массового импорта используйте [пример TXT](examples/queue_import_example.txt). Перед импортом показываются аккаунты, число новых постов, дубли и ошибки.
4. В редакторе оставьте дату пустой для обычной очереди либо задайте `ГГГГ-ММ-ДД ЧЧ:ММ`. Первый обычный пост ждёт полный интервал.
5. Пауза очереди сохраняется после перезапуска. «Повторить / сейчас» — явная отправка выбранной записи даже при паузе.

## Сохранность и восстановление отправок

SQLite работает в режиме WAL. Перед сетевой отправкой сохраняются запись, постоянный record key и подготовленное содержимое поста, включая ссылки на загруженные вложения. После обрыва проверяется тот же ключ; новый ключ для неопределённой отправки не создаётся.

- **Ожидает:** пост можно редактировать, перемещать и удалять.
- **Отправляется:** изменение и удаление заблокированы до результата.
- **Проверка результата:** временная ошибка; автоматический повтор с увеличивающейся задержкой и учётом ограничений сервера.
- **Ошибка:** пост остаётся в очереди с причиной. Исправьте данные или нажмите «Повторить / сейчас». При неясном результате сначала проверяется прежняя отправка.

При ошибке авторизации очередь аккаунта приостанавливается. Ошибочный текст не превращается в успешную публикацию и не теряется. Дедупликация истории различает публикацию и пропуск. При сравнении с профилем исключаются чужие репосты, ответы и посты с вложениями; сверяются только последние 100 записей. Это не полная синхронизация всей истории и не координация двух одновременно работающих компьютеров.

Запуск второй копии EXE с той же папкой данных поднимает уже работающее окно. При завершении интерфейс остаётся отзывчивым, пока фоновые задачи заканчивают работу. Незавершённая отправка сохраняется для следующего запуска.

## Данные и резервные копии

Обычно данные хранятся в `data` рядом с EXE. Для совместимости поддерживается база непосредственно рядом с EXE; при недоступной для записи папке используется `%LOCALAPPDATA%\AgniaBlueskySuite`. Реальный путь открывается кнопкой «Папка данных». Для разработчиков доступна переменная `AGNIA_BLUESKY_DATA_DIR`.

Переносимые App Password и сессии зашифрованы ключом `.secret_key` в папке данных. Доступ к базе **вместе с ключом** позволяет расшифровать аккаунты. Старые DPAPI-записи читаются на исходном компьютере, но больше не переводятся автоматически в другой формат. Ошибка записи или потеря ключа не маскируется созданием нового.

Автоматические локальные ZIP-копии создаются раз в сутки (проверка при запуске, завершении и каждые 15 минут); хранятся последние семь. Они включают базу, ключ и используемые медиа. Для передачи или хранения отдельно используйте «Сохранить с паролем»: архив защищён AES-GCM, ключ выводится из пароля через scrypt. Пароль от архива восстановить нельзя.

При восстановлении проверяются пароль, база и вложения; текущие данные предварительно копируются. Замена выполняется при следующем запуске, до старта фоновых задач. Логи не входят в резервную копию. Автоматические копии на том же диске не защищают от поломки диска.

## Медиа и ограничения

- JPEG, PNG и WebP копируются в хранилище приложения, исправляется ориентация EXIF; изображения уменьшаются до 2048 пикселей по большей стороне и до 1 МБ. При необходимости изображение с прозрачностью преобразуется в JPEG на белом фоне. Оригинал не меняется.
- Видео: один MP4 до 50 МиБ. Предпросмотр показывает имя и описание; встроенного видеоплеера нет. Сервер может отклонить неподдерживаемый кодек или видео, превышающее ограничения аккаунта; запись останется с ошибкой.
- Карточка ссылки: URL, заголовок и описание вводятся вручную. Страницы по URL автоматически не загружаются.
- Для поста требуется непустой текст; проверяются 300 графем и 3000 байт UTF-8.
- Экспорт пока текстовый: изображения и видео из удалённого профиля не скачиваются.
- Календарь работает, пока приложение запущено. Выключенный компьютер не публикует посты.
- Работа с реальными аккаунтами и доставка медиа требуют сети; офлайн-тесты не заменяют проверку фактической публикации на сервере.

## Разработка

Python 3.12:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest
.venv\Scripts\python -m ruff check .
.venv\Scripts\python -m PyInstaller --clean --noconfirm AgniaBlueskySuite.spec
dist\AgniaBlueskySuite.exe --smoke-test
```

Реальный офлайн-тест Tk: `python tests/gui_smoke.py` (Linux: `xvfb-run -a python tests/gui_smoke.py`). CI проверяет интерфейс на Linux, тесты на Windows, собирает один EXE, запускает packaged smoke-test и только после успешных проверок публикует новый релиз из `main`.

Аудит и границы проверки: [docs/AUDIT_1.3.1.md](docs/AUDIT_1.3.1.md).
