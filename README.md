# Agnia Bluesky Suite

Единое автономное Windows-приложение для нескольких аккаунтов Bluesky: лайкинг, фолловинг, ручной постинг, постоянные очереди, экспорт и подготовка текстов для AI. Интерфейс и фоновые задачи работают напрямую через Bluesky API — браузер и консоль не нужны.

Проект создан в отдельном репозитории после аудита трёх исходных программ: `bluesky-automation-tool`, `bluesky-queue-poster` и `bluesky-posts-exporter`. Старые репозитории остаются архивными источниками и приложением не изменяются.

## Скачать

Откройте раздел **Releases**, скачайте `AgniaBlueskySuite-v1.0.0-windows-x64.zip`, распакуйте архив и запустите `AgniaBlueskySuite.exe`. Установщик не требуется.

При первом запуске Windows SmartScreen может показать предупреждение, потому что EXE не подписан коммерческим сертификатом. Проверьте SHA-256 по `SHA256SUMS.txt` из Release.

## Возможности

- **Лайки** — домашняя лента, рекомендации или поиск; пропуск своих постов, ответов, репостов и уже обработанных записей; пауза и остановка; настраиваемые задержки и длинные перерывы.
- **Фолловинг** — вставка или импорт списка handle/ссылок; проверка текущей подписки; лимит, пауза, остановка и журнал результата.
- **Постинг** — ручная текстовая публикация от выбранного аккаунта с понятными ошибками API или добавление текста в очередь.
- **Очередь** — импорт больших UTF-8/Windows-1251 TXT, маршрутизация по `@account:`, независимое расписание каждого аккаунта, jitter, пауза, публикация сейчас, пропуск, удаление и изменение порядка.
- **Экспорт** — собственные посты без репостов, фильтр ответов и дат, дедупликация, отдельные UTF-8 TXT и объединённый файл очереди.
- **Экспорт для AI** — `original_posts_<handle>.txt` отдельно для каждого выбранного аккаунта, без репостов и ответов.
- **Аккаунты** — два и более профиля, быстрое переключение, проверка входа и состояние подключения.
- **Настройки** — тёмная/системная/светлая тема, системный трей, автозапуск Windows, старт свёрнутым, интервалы, лимиты и общий журнал.

## Быстрый старт

1. В Bluesky откройте **Settings → Privacy and security → App passwords** и создайте отдельный App Password для программы.
2. В разделе **Аккаунты** добавьте handle и App Password, затем нажмите **Проверить**.
3. Добавьте второй профиль тем же способом. Программа поддерживает и больше двух аккаунтов.
4. Для очереди используйте формат из [`examples/queue_import_example.txt`](examples/queue_import_example.txt). Каждый блок отделяется строкой `---`.
5. Настройте интервал и jitter отдельно в карточке каждого аккаунта. По умолчанию первый пост ожидает один полный интервал, а не публикуется сразу.

## Сохранность данных

- База SQLite хранится в `%LOCALAPPDATA%\AgniaBlueskySuite\agnia_bluesky.db`; режим WAL и транзакции защищают очередь от частично записанных изменений.
- App Password шифруется Windows DPAPI и расшифровывается только тем же пользователем Windows на том же компьютере.
- Ожидающие и завершённые посты дедуплицируются отдельно для каждого аккаунта.
- У каждой записи очереди заранее есть постоянный Bluesky record key. При неопределённом результате сетевого запроса программа проверяет этот ключ перед повтором, снижая риск двойной публикации.
- При сетевой/API-ошибке элемент остаётся в очереди; повтор выполняется с увеличивающейся паузой до 30 минут и небольшим jitter.
- Расписание, паузы, попытки, ошибки и история сохраняются после каждого изменения и восстанавливаются после перезапуска.

## Журналы и экспорт

Журнал находится в `%LOCALAPPDATA%\AgniaBlueskySuite\logs\app.log` и ротируется автоматически. Экспорт по умолчанию сохраняется в `%LOCALAPPDATA%\AgniaBlueskySuite\exports`.

## Ограничения

- Версия 1.0 публикует и экспортирует текст. Загрузка изображений/видео, карточек ссылок, опросов и явное построение rich-text facets пока не реализованы.
- Bluesky может менять лимиты и правила API. Автоматические лайки и массовый фолловинг следует использовать умеренно и в соответствии с правилами сервиса.
- EXE собирается GitHub Actions без цифровой подписи издателя; поэтому возможен SmartScreen.
- DPAPI повышает защиту локального секрета, но не заменяет безопасную учётную запись Windows и резервное копирование базы.
- Постоянный record key заметно уменьшает риск повтора после обрыва связи, но ни один клиент не может обещать абсолютную «ровно один раз» доставку при всех сбоях сервера.

## Разработка и проверка

Требуется Python 3.12:

```powershell
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
.venv\Scripts\python -m pytest
.venv\Scripts\pyinstaller --clean --noconfirm AgniaBlueskySuite.spec
dist\AgniaBlueskySuite.exe --smoke-test
```

CI выполняет тесты, собирает один оконный EXE, запускает его офлайн smoke-test и создаёт ZIP с контрольными суммами. Подробности архитектуры и аудита находятся в папке `docs`.
